# Invariantes da interface

Regras que nenhuma mudança pode quebrar, humana ou de agente. Cada
capítulo do livro acrescenta as suas; cada regra diz como é verificada.

| ID | Regra | Verificação |
|---|---|---|
| UI-00 | O código do front chama a API por caminho relativo (`/api/...`); nenhum endereço de servidor no código. | `grep -rn "localhost:3000" src` vazio |
| UI-01 | Lista usa key do domínio (o `id`), nunca o índice do array. | `Ala.test.tsx`: "anotação acompanha o paciente" |
| UI-02 | Componente nunca é definido dentro de outro componente. | `oxlint`: `react/no-unstable-nested-components` |
| UI-03 | Estado nunca é alterado no lugar: atualização cria objeto ou array novo. | `Ala.test.tsx`: "prioridade no cartão e no detalhe" |
| UI-04 | Ação que cria registro trava no clique (ref, sem esperar render) e o servidor recusa duplicata (409). `disabled` é aviso visual, não trava. | `FormAdmissao.test.tsx` e `medicoes/cap06.py` |
| UI-05 | A tela valida para ajudar; o servidor valida para decidir. Erro do servidor aparece no campo. | `FormAdmissao.test.tsx`: "mostra o que o servidor recusou" |
| UI-06 | Efeito só sincroniza com sistema externo; nunca copia um estado para outro. | `oxlint`: `react/set-state-in-effect` como erro |
| UI-07 | Efeito que busca dados cancela o pedido na limpeza (AbortController). | `BuscaProntuario.test.tsx`: "resposta velha não sobrescreve a nova" |
| UI-08 | Feature não importa outra feature; `api/` e `compartilhado/` não importam `features/` nem `app/`; nenhum ciclo. O que duas features usam sobe para `compartilhado/`. | `npm run fronteiras` (dependency-cruiser) |
| UI-09 | Só `src/api/` chama `fetch`. Resposta de erro vira `ErroHttp` com o status; nenhuma tela interpreta `Response` cru. | `oxlint`: `no-restricted-globals` |
| UI-10 | Erro esperado (403, 409) vira aviso no lugar dele. 401 não é aviso: leva ao login (UI-21). Erro inesperado sobe ao `LimiteDeErro` do painel: o painel avisa e o resto da tela continua. | `LimiteDeErro.test.tsx` e `Busca.test.tsx`: "sem permissão, avisa em vez de quebrar" |
| UI-11 | Cor, espaço e raio vêm de token (`var(--...)`); hexadecimal só em `src/estilo/tokens.css`. Todo par de texto dos tokens passa 4,5:1 nos dois temas; o contorno de foco, 3:1. | `tokens.test.ts` |
| UI-12 | Toda parada de teclado tem foco visível: `outline: none` só com substituto. Informação nunca só por cor: o selo escreve o risco. | `medicoes/vigia_a11y.py` (repositório do livro) |
| UI-13 | Botão é `Botao` (variante e `type="button"` por padrão); `<button>` cru só dentro de `compartilhado/Botao.tsx`. Aviso ao usuário é `Aviso`: `erro` vira `role="alert"`, `info` vira `role="status"`. | `oxlint`: `react/forbid-elements` |
| UI-14 | Caixa sobre a tela é `Modal` (`<dialog>` com `showModal()`): o foco entra, Esc fecha, o fundo fica inerte e o foco volta a quem abriu. Ação sem volta pede confirmação, com Cancelar primeiro. | `Ala.test.tsx`: "alta pede confirmação num diálogo"; `medicoes/cap10.py` |
| UI-15 | Estado que muitas features leem (preferências de exibição) mora num provedor em `compartilhado/`, que recebe a tela como `children`: um contexto por assunto, ações num contexto próprio e estável. Nome de paciente na tela passa por `useExibirNome()`. Dado do servidor nunca vai para contexto. | `App.test.tsx`: "modo discreto não mostra nome inteiro"; `medicoes/cap11.py` |
| UI-16 | Fluxo com fases e regras de transição (o assistente de admissão) mora num reducer puro, com o estado em união discriminada por fase: enviando não tem passo, admitido não tem dados. Ação fora da fase é ignorada pelo reducer, não só pelo botão. | `assistente.test.ts` (sem tela) e `Assistente.test.tsx` |
| UI-17 | O que cabe num link mora na URL: termo de busca (`?q=`), página e paciente aberto (`/pacientes/:id`). Campo ligado à URL navega com `replace` e `flushSync`. Navegação interna é `Link`/`NavLink`, nunca `<a href>`. | `rotas.test.tsx`: "a busca mora na URL"; `medicoes/cap13.py` |
| UI-18 | Erro de rota aparece dentro do layout (`ErroDeRota` numa rota sem caminho) e caminho desconhecido cai no `*`. Loader traduz 404 em mensagem; sessão não é assunto de loader (UI-21). `volta` só aceita caminho interno. | `rotas.test.tsx` |
| UI-19 | Dado do servidor mora no cache do TanStack Query, com chave em árvore (`["pacientes", ...]`). Nunca é copiado para `useState` nem para contexto. Mutação invalida `["pacientes"]` ao terminar; edição otimista guarda o valor anterior e o devolve no erro. | `rotas.test.tsx`: "a lista mostra o nome editado", "trocar de paciente troca o detalhe"; `medicoes/cap14.py` |
| UI-20 | O contrato com a API mora em `docs/API.md` e em `src/api/pacientes.ts`. Mudança de formato de resposta muda os dois e os testes no mesmo commit. | revisão; `npm run gate` |
| UI-21 | Quem entrou é dado do servidor: mora no cache (`["sessao"]`), lido de `/api/auth/me`. Nada de sessão, token ou "está logado" em `localStorage`, `sessionStorage` ou `useState`. Rota protegida fica sob o middleware `exigirSessao`, que decide antes de qualquer loader. 401 em qualquer pedido marca a sessão como encerrada e o `Layout` leva a `/entrar?volta=`. Entrar e sair limpam o cache; sair, depois de deixar as rotas protegidas. | `rotas.test.tsx` (sessão e permissão); `medicoes/cap15.py`; `grep -rn "localStorage" src` vazio |
| UI-22 | Botão de ação que um papel não pode usar some por `usePode(permissão)`, com as permissões que `/api/auth/me` devolve; nunca por nome de papel. Toda ação escondida tem 403 na API, provado chamando a rota direto. 403 avisa no lugar e não leva ao login. | `rotas.test.tsx`: "recepção não vê Inativar", "403 avisa ali mesmo"; `medicoes/porta_dos_fundos.py` |
| UI-23 | Nada de segredo no navegador: toda variável `VITE_` vai para o bundle, legível por qualquer um; credencial de serviço fica no servidor. HTML vindo de dado nunca entra por `dangerouslySetInnerHTML`. | `grep -rn "import.meta.env" src` só com configuração pública; `oxlint`: `react/no-danger` |
| UI-24 | Teste simula a rede na fronteira, com o MSW (`src/teste/rede.ts` e `apiFalsa`), e lê a tela pelo papel e pelo rótulo. Nunca `vi.mock` de módulo da aplicação: hook, consulta ou serviço mockado passa mesmo com o HTTP quebrado. Pedido que nenhum teste descreveu é erro. A jornada E2E (`npm run e2e`) roda contra a API real antes de toda entrega. | `grep -rn "vi.mock" src` vazio; `onUnhandledFrame: "error"`; `e2e/jornada.spec.ts` |
| UI-25 | Memoização é do React Compiler, ligado no build. `useMemo`, `useCallback` e `memo` só como válvula de escape, com medição antes e depois no Renderômetro. Otimização sem número não entra. | `vite.config.ts`; `medicoes/cap16.py` |
| UI-26 | Permissão de `/api/auth/me` diz o que o papel pode fazer em geral; o contexto (autoria, status, plantão) só a API confere. A tela mostra a ação pela permissão e pela regra que ela conhece (autor, aberto) e trata o 403 no lugar. Leitura que o papel não tem não é pedida: o loader confere a permissão antes. | `atendimentos.test.tsx` (A2, A3, A5); `porta_dos_fundos.py` em `/atendimentos/e1` |
